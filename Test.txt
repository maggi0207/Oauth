# PHASE 2: UNDERSTAND THE API CONTRACT

The Facts API exposes the following endpoint:

GET /api/ActiveReaction/search

Query parameters:

- inputActive: string (optional)
- outputActive: string (optional)

The endpoint supports:
- Input-only searches.
- Output-only searches.
- Searches with both input and output.
- Partial, case-insensitive matching.
- AND matching when both parameters are provided.

At least one search parameter must contain a non-empty value.

The API returns HTTP 200 with an array of results.

Response structure:

[
  {
    "activeIprId": 1,
    "chemicalEquation": "2Ca + Cl2 => 2CaCl",
    "inputActives": "Cypruflone, quinoline oxazolidinone",
    "outputActives": "isopropylamine, procymidone"
  },
  {
    "activeIprId": 5,
    "chemicalEquation": "dummy entry",
    "inputActives": "Magnesium",
    "outputActives": "cafensole"
  }
]

Verify the actual generated API service and existing DTOs before
implementing the integration.

Do not create duplicate interfaces if the project already has
appropriate generated types.

B. Output Active only

  call the API with outputActive.
- Display the matching results.

C. Both fields populated

- Display only the results returned by the backend.

- Treat whitespace-only values as empty.

- Allow users to enter partial active names.
- Let the backend handle matching.

  changes the API's search semantics.
