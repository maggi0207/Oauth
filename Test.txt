# PHASE 2: IMPLEMENT FORMULATION CORE SEARCH API

Implement the search functionality in the
Formulation Core repository first.

## 2.1 API Endpoint

Create the endpoint using the existing routing
conventions.

HTTP method: GET

Endpoint:

/api/ActiveReaction/search

Query parameters:

- inputActive (optional)
- outputActive (optional)

Example requests:

GET /api/ActiveReaction/search?inputActive=Cobalt

GET /api/ActiveReaction/search?outputActive=Sodium

GET /api/ActiveReaction/search?inputActive=Cobalt&outputActive=Sodium

Use GET with query parameters, following the
existing API conventions.

## 2.2 Search Behavior

Implement the following behavior:

| Input Active | Output Active | Expected behavior |
|---|---|---|
| Cobalt | Sodium | Apply both filters using AND |
| Cobalt | Empty | Search only by Input Active |
| Empty | Sodium | Search only by Output Active |
| Empty | Empty | Return HTTP 400 |
| Whitespace | Sodium | Search only by Output Active |
| Cobalt | Whitespace | Search only by Input Active |
| Whitespace | Whitespace | Return HTTP 400 |

Requirements:

1. Both parameters are individually optional.
2. At least one parameter must contain a
   non-whitespace value.
3. Trim leading and trailing whitespace.
4. Treat null, empty, and whitespace-only
   values as empty.
5. When both parameters are populated,
   apply AND logic.
6. When only one parameter is populated,
   apply only that filter.
7. Never return the entire dataset when
   both parameters are empty.
8. Support partial matching.
9. Follow existing case-sensitivity conventions.

If the existing business logic conflicts with
these rules, identify the conflict before
changing the behavior.

## 2.3 Active Ingredient Filtering

Inspect the existing data model and determine
how input and output active ingredients are
represented.

Use the existing Side property or equivalent
business logic.

Ensure that:

- Input Active searches only input ingredients.
- Output Active searches only output ingredients.
- Both filters match the same Active IP.
- Multiple ingredients per IP are supported.
- Matching multiple ingredients does not
  create duplicate IP results.

Do not assume that an IP contains only one
input or output active ingredient.

## 2.4 Sorting

Sort the search results by Chemical Equation.

Use the existing sorting conventions.

Ensure sorting is deterministic and handles
null or empty chemical equations.

## 2.5 Response Structure

Inspect the existing DTOs and data model.

The response must contain:

- ActiveIpId
- ChemicalEquation
- InputActives
- OutputActives

Use the correct existing property types.

Ensure that the response can later be consumed
by the Angular Active IP Search table.

Do not introduce unnecessary DTOs if suitable
ones already exist.

## 2.6 Controller and Service

Implement the endpoint using the existing
ActiveReactionController and service architecture.

Follow established conventions for:

- Asynchronous methods
- Dependency injection
- Request validation
- Error handling
- Logging
- CancellationToken, if supported

Avoid unrelated refactoring.

## 2.7 Swagger Documentation

Update Swagger documentation to describe:

- Endpoint purpose
- Query parameters
- Search behavior
- Successful response
- HTTP 400 for missing search criteria
- Other relevant error responses

Ensure the endpoint is visible in Swagger.
