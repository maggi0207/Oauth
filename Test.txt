# Task: Final Code Review – Active IPR Search UI
Jira: FOREP-2713
Repository: Facts UI (Angular)

Perform a comprehensive code review of the Active IPR Search
UI implementation and its integration with the Facts API.

IMPORTANT:
This is a REVIEW-ONLY task.
Do not modify any files or implement fixes.
Identify issues and provide recommendations.

## 1. Read Project Instructions

Before reviewing:
- Read the applicable repository instructions and skills.
- Understand the existing Angular architecture.
- Follow the established coding patterns.
- Inspect existing API integrations and similar components.
- Review the complete implementation and Git diff.

Do not assume the implementation is correct simply because
the application builds successfully.

## 2. Review API Integration

Verify that the Angular UI correctly integrates with:

GET /api/ActiveReaction/search

Query parameters:
- inputActive (optional)
- outputActive (optional)

Expected response:

[
  {
    "activeIprId": 1,
    "chemicalEquation": "2Ca + Cl2 => 2CaCl",
    "inputActives": "Cypruflone, quinoline oxazolidinone",
    "outputActives": "isopropylamine, procymidone"
  }
]

Verify:
- The correct API endpoint is used.
- Query parameters are passed correctly.
- URL encoding is handled properly.
- The generated API client is used if required by
  the existing architecture.
- The response DTO matches the backend contract.
- The API base URL is configured correctly.
- Authentication and authorization follow existing patterns.
- HTTP errors are handled correctly.

Compare the implementation with existing API integrations
in the project.

## 3. Review Search Functionality

Verify all the following scenarios:

1. Input Active only.
2. Output Active only.
3. Both fields populated.
4. Both fields empty.
5. Whitespace-only input.
6. Partial active-name searches.
7. Case-insensitive matching.
8. Search returning multiple results.
9. Search returning no results.
10. API failure.

Confirm that:
- At least one search field is required.
- Both parameters are sent when both fields are populated.
- Empty parameters are handled correctly.
- The UI does not introduce additional filtering that
  conflicts with backend search semantics.
- Duplicate requests are prevented appropriately.
- Search results are updated correctly after each request.

## 4. Review UI and Grid Integration

Inspect the existing Active IPR Search component.

Verify:
- The Input Active and Output Active fields are correctly bound.
- The Search button triggers the API.
- The Clear button resets the form and results.
- The Search Results grid displays the API response correctly.
- Chemical Equation, Input Actives, and Output Actives
  are mapped to the correct columns.
- Empty results display the appropriate message.
- Loading indicators work correctly.
- Error messages are displayed appropriately.
- The Create New Active IPR action still works.
- Existing layout and styling have been preserved.

Check for unnecessary UI changes or duplicated logic.

## 5. Review Angular Coding Standards

Verify:
- Existing component and service patterns are followed.
- Dependency injection is implemented consistently.
- TypeScript types are correct.
- Existing interfaces and generated DTOs are reused.
- Observables and subscriptions are handled correctly.
- Memory leaks are avoided.
- Async operations and loading states are managed correctly.
- No unnecessary dependencies or abstractions were introduced.
- No hardcoded URLs or placeholder data remain.
- No unrelated files were modified.

## 6. Review Error Handling and Edge Cases

Check:
- HTTP 400 responses.
- HTTP 401 and 403 responses.
- HTTP 404 responses.
- HTTP 500 responses.
- Empty response arrays.
- Null or unexpected response values.
- Network failures.
- Repeated searches while a request is pending.
- Clearing the form while a request is pending.
- Stale responses overwriting newer search results.

Identify any cases that could cause incorrect results,
uncaught exceptions, or a broken UI.

## 7. Review Unit Tests

Inspect the existing unit tests and verify coverage for:

- Input-only search.
- Output-only search.
- Both search parameters.
- Empty input validation.
- Whitespace handling.
- Successful API response.
- Empty results.
- API errors.
- Loading state.
- Clear button.
- Grid data binding.
- Create New Active IPR functionality.

Check whether the tests actually validate the behavior
or merely verify that methods were called.

Run the relevant tests and Angular build if possible.

Report actual results. Do not claim that unexecuted tests passed.

## 8. Review Backend Contract Compatibility

Compare the Angular implementation with the actual

Verify:

- Optional parameter behavior.
- Empty search behavior.

  FormulationCoreRepoClient integration.
